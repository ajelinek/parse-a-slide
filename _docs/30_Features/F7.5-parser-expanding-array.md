# F7.5 Parser: Expanding Array Approach (Clean Slate)

## Overview

**Starting from scratch** - Build a dramatically simplified parser using an expanding array approach. The current implementation is overly complex and not scalable. This is a complete rewrite.

## Core Concept

**Single Expanding Array**: Process entry fragment → expand fragments in-place → create slides with navigation.

```
Initial: [c1, @fragment.md, c3]
After expansion: [c1, frag1, frag2, c3]
Result: Slides with proper IDs and navigation
```

## Simplified Content Splitting

**New Simple Interface**: Count carrots (^) to determine delimiter level.

```typescript
interface SplitContent {
  content: string
  delimiterLevel: number    // Count of ^ characters (^^ = level 2, ^^^ = level 3)
}
```

### Delimiter Level Detection
```
---         → delimiterLevel: 0 (no carrots)
--- ^       → delimiterLevel: 1 (one carrot)
--- ^^      → delimiterLevel: 2 (two carrots)
--- ^^^     → delimiterLevel: 3 (three carrots)
```

## Minimal Global State

### 1. Working Array Item
```typescript
interface WorkingItem {
  content: string
  delimiterLevel: number
  isEmbeddedFragment: boolean  // Passed to splitter, applied to all items
}
```

### 2. Simple Parser State
```typescript
interface ParserState {
  fragmentMap: Map<string, Fragment>

}
```

## Ultra-Simple Algorithm (Real Pseudocode)

### Main Process
```
MAIN PARSE FUNCTION:
  1. Find entry fragment (error if none)
  2. Initialize working array: split_fragment_content(entry, isEmbeddedFragment=false)
  3. Loop through working array:
     - If item is fragment → splice in its splits with isEmbeddedFragment=true
     - Continue until no more fragments
  4. Create slides with IDs and navigation
  5. Return slides
```

### Expansion Loop
```
EXPANSION LOOP:
  index = 0
  WHILE index < array length:
    item = working_array[index]
    
    // Main loop determines if content contains fragment links
    IF content contains markdown links ending in .fragment.md:
      // Pass isEmbeddedFragment=true to splitter
      fragment_splits = split_fragment_content(fragment, isEmbeddedFragment=true)
      
      working_array.splice(index, 1, ...fragment_splits)
      // Don't increment index - process new items
      CONTINUE
    
    index = index + 1
  END WHILE
```

### Slide Creation
```
SLIDE CREATION:
  slides = []
  parent_stack = []
  previous_level = 0
  
  FOR each item in working_array:
    // Update parent stack based on level changes
    level_difference = item.delimiterLevel - previous_level
    
    IF level_difference > 0:
      // Going deeper - push previous slide ID
      parent_stack.push(previous_slide_id)
    ELSE IF level_difference < 0:
      // Going shallower - pop multiple levels
      FOR i = 1 to abs(level_difference):
        parent_stack.pop()
    // If level_difference = 0, no stack change needed
    
    // Generate slide ID 
    slide_id = generate_id(parent_stack, slide_counter)
    slide_counter = slide_counter + 1
    
    // Create slide with navigation
    slide = create_slide(item, slide_id, parent_stack)
    slides.add(slide)
    
    // Update for next iteration
    previous_level = item.delimiterLevel
    previous_slide_id = slide_id
  END FOR
  
  RETURN slides
```

## Key Functions (Conceptual)

### 1. Simple Content Splitter
```
SPLIT FRAGMENT CONTENT FUNCTION:
  INPUT: fragment content string, isEmbeddedFragment boolean
  
  1. Find all delimiter lines (--- with carrots)
  2. Split content by these delimiters
  3. For each section:
     - content = the text between delimiters
     - delimiterLevel = count ^ characters on delimiter line
     - isEmbeddedFragment = passed in value (applied blindly to all)
  
  OUTPUT: array of WorkingItem objects
  
  NOTE: Splitter doesn't need to detect fragments - just applies
        the isEmbeddedFragment value passed from main loop
```

### 2. Parent Stack Updates
```
UPDATE PARENT STACK:
  INPUT: current delimiter level, previous delimiter level
  
  1. Calculate level difference = current - previous
  
  2. If level difference > 0:
     - Push previous slide ID onto parent stack
     - (Going deeper by any amount)
  
  3. If level difference < 0:
     - Pop multiple levels from parent stack
     - Remove abs(level_difference) items from stack
     - (Going shallower by multiple levels)
  
  4. If level difference = 0:
     - No change to parent stack
     - (Staying at same level)
```

### 3. Slide ID Generation  
```
GENERATE SLIDE ID:
  INPUT: parent stack, slide counter
  
  1. If parent stack empty: "S" + slide_counter
  2. If parent stack has items: parent_id + "C" + child_counter
  
  Examples:
  - S1, S2, S3 (top level)
  - S1C1, S1C2 (children of S1)
  - S1C1C1 (grandchild)
```

### 4. Fragment Detection
```
IS EMBEDDED FRAGMENT:
  INPUT: content string
  
  1. Search for markdown links in content: [text](path)
  2. Extract the path from any markdown links
  3. Check if path ends with '.fragment.md'
  4. Return true if any fragment links found
  
  Examples:
  - [My Fragment](./fragments/intro.fragment.md) → true
  - [See Details](../shared.fragment.md) → true  
  - [Normal Link](./page.md) → false
  - Regular content without links → false
```

## Benefits of Clean Slate Approach

### 1. Dramatic Simplification
- **Single expanding array** - no complex objects
- **No recursion** - simple while loop
- **No buffering** - direct splice operations
- **Minimal state** - just parent stack and counter

### 2. Clear Mental Model
- **"Replace fragment with its content"** - intuitive concept
- **Carrot counting** - simple delimiter level detection
- **In-place expansion** - no intermediate collections
- **Linear processing** - easy to understand and debug

### 3. Eliminates All Current Complexity
- **No ContentProcessor** - deleted entirely
- **No complex splitting** - just carrots and content
- **No inheritance calculations** - parent stack handles it
- **No buffer flushing** - no buffers exist

### 4. Scalable Foundation
- **Easy to extend** - clear expansion points
- **Easy to test** - isolated functions
- **Easy to debug** - all state visible
- **Easy to optimize** - simple data structures
